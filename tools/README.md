# Tools

- **devtools/**: Browser extension (Chrome/Firefox) for debugging Owl components. Provides a devtools panel to inspect component tree, state, and lifecycle.
- **playground/build_monaco.mjs**: Bundles the Monaco editor and its workers for the playground.
- **compile_owl_templates.mjs**: CLI tool that compiles Owl XML templates into JavaScript. Reads template files from provided paths and writes compiled output to a file.
- **playground/server.py**: Python HTTP server that serves the playground locally, resolving Owl builds and disabling caching. Run with `npm run playground:serve`.
- **odoo_migration/**: Odoo template migration and compilation checks, including template inheritance comparisons between Owl builds. The checkers exit 2 on a root that does not exist or holds no template, and on a `packages/owl/dist` built from other sources than those beside it.
- **vendor_odoo.mjs**: Builds this checkout and vendors it into Odoo: `npm run vendor:odoo -- --check` compares the build with `web/static/lib/owl/` and the `owl` entry of `web/static/lib/versions.json` and exits 1 on a difference; without `--check` it copies the three files and updates that entry (commit, checksums, version). `--check` also applies Odoo's `check_vendored_libs.py` rules: the checksums pin exactly the three files, the entry's `probe` matches, each file's `var buildHash` is the pinned commit's. The version written is the build's own (`owl-runtime/src/version.ts`); a `packages/owl/package.json` that disagrees is refused. `--odoo <path>` names the Odoo checkout (default: `../odoo` beside this one, nothing else). Refused: any uncommitted change to a tracked file anywhere in the checkout (`git status --porcelain --untracked-files=no` not empty) and any untracked file under `packages/*/src`; untracked files elsewhere (e.g. `__pycache__`) are allowed.
- **benchmark_reactivity.mjs**: Debug-validates tracked reads, selective notifications, collection mutations and proxy/observe iterators, then measures them with logging disabled. Run with Node 26 (refused below) using `npm run bench:reactivity -- --baseline /path/to/baseline/owl --output temp/reactivity.json`. The baseline is optional. Rounds alternate module order; source hashes and checksums are checked again after timing. Each reported iteration performs one read or write, two mutations for insert/delete, or consumes 32 iterator values. Tracked-read loops include effect creation/disposal, amortized over the loop. The Vitest core benchmarks also expose these workloads, with 128 iterations per sample. Treat its cross-workload rankings as workload cost comparisons.
- **benchmark_browser.mjs**: Uses local Chrome to compare selection, 20-row updates, and navigation to a detail view and back in a 200-row app: `npm run bench:browser -- --baseline /path/to/baseline/owl --output temp/navigation.json`. Checks committed DOM, selective render counts and subscription cleanup before and during timing. It builds each checkout independently, adding diagnostic exports from the same core instance, and removes its browser profile and HTTP listener afterward. Commit latency includes animation-frame waits; instrumented render-function time covers only part of the pipeline. This synthetic app does not measure Odoo application performance. Run timing comparisons serially and repeat with baseline/candidate roots reversed to check order effects.
